# 카드 강화 설계서 — 「수련」

작성 2026-09-09 · 기획 클로드 · 구현 코덱스
기준: `cards.json` 51장 (커밋 `ff6c472`) · 엔진 `js/engine.js` · 규약 `DESIGN.md`

## 0. 한 줄

같은 카드로 이길수록 그 카드가 조금씩 세지는 **수련 단계**를 넣는다. 최대 3단계, 상한은 체력 +20과 1★ 기술 피해 +10이다.

## 1. 왜 이 형태인가

**공격·방어·지력 별점은 전투에 쓰이지 않는다.** 엔진은 `card.stats`를 한 번도 읽지 않는다. 실제로 읽는 것은 체력, 기술의 피해와 별 소모, 특성, 속성뿐이다. 그래서 강화는 **체력과 기술 피해에만** 붙인다. 별점을 올리는 강화는 화면에는 세져 보이는데 전투는 그대로여서 아이를 속이게 된다.

**상한을 낮게 잡는 이유.** 2026-09-09 균형 조정에서 51장을 전부 붙여 본 결과, 승률을 가장 크게 움직이는 단일 값이 체력이었다. 체력 +20은 한 대를 더 버티게 해 주는 정도이고, 이보다 크면 균형이 무너진다.

**화폐를 만들지 않는다.** 모으고 쓰는 화폐는 다섯 살에게 한 단계 어렵다. 이긴 카드가 그 자리에서 자라는 편이 바로 이해된다.

## 2. 규칙

### 2-1. 얻는 법

그 카드로 대결에서 **이기면** 수련이 1 오른다. 지면 그대로다. **줄어들지 않는다.**

| 수련 | 필요한 누적 승수 | 효과 |
|---|---|---|
| 0 | 0 | 없음 |
| ★ | 1 | 체력 +10 |
| ★★ | 3 | 체력 +20 |
| ★★★ | 6 | 체력 +20, 가장 싼 기술의 피해 +10 |

"가장 싼 기술"은 별 소모가 가장 적은 기술이고, 같으면 배열에서 앞선 것이다. 피해가 0인 기술은 대상이 아니며, 그 경우 그다음으로 싼 피해 기술을 올린다.

상대는 수련하지 않는다. 아이가 세지는 것을 실제로 느끼게 하는 것이 목적이다.

### 2-2. 저장

카드별로 승수만 저장한다. 기존 카드별 저장 방식(`quizMemoryKey`, `js/app.js:136`)과 같은 결이다.

```js
  function trainKey(cardId) { return "card_train_" + cardId; }
  function trainWins(cardId) {
    try { return Math.max(0, Math.min(99, Number(localStorage.getItem(trainKey(cardId))) || 0)); }
    catch (e) { return 0; }
  }
  function trainLevel(cardId) {
    const wins = trainWins(cardId);
    return wins >= 6 ? 3 : wins >= 3 ? 2 : wins >= 1 ? 1 : 0;
  }
```

`localStorage`가 막힌 환경에서도 게임이 멈추면 안 된다. 읽기·쓰기를 모두 `try`로 감싸고, 실패하면 수련 0으로 동작한다.

### 2-3. 적용

**`cards.json`을 고치지 않는다.** 대결을 시작할 때 강화된 사본을 만들어 엔진에 넘긴다. 원본을 건드리면 컬렉션 화면과 고정 해시 검사가 전부 어긋난다.

```js
  function trainedCard(card) {
    const level = trainLevel(card.id);
    if (!level) return card;
    const bonusHp = level === 1 ? 10 : 20;
    const copy = Object.assign({}, card, { hp: card.hp + bonusHp });
    if (level >= 3) {
      const attacks = card.attacks.map(function (a) { return Object.assign({}, a); });
      const target = attacks
        .map(function (a, i) { return { a: a, i: i }; })
        .filter(function (x) { return Number(x.a.dmg) > 0; })
        .sort(function (x, y) { return x.a.cost - y.a.cost || x.i - y.i; })[0];
      if (target) target.a.dmg += 10;
      copy.attacks = attacks;
    }
    return copy;
  }
```

`createGame`에 넘기는 플레이어 카드만 `trainedCard`를 거친다. 상대 카드는 그대로다.

### 2-4. 승리 기록

`finishBattle`(`js/app.js:2775`)에서 `victory`가 참일 때만 1 올린다. 같은 판이 두 번 세지 않도록 `battleSession`으로 한 번만 실행되게 막는다.

## 3. 화면

### 3-1. 카드 위 표시

카드 이름 옆에 작은 배지를 둔다. 수련 0이면 아무것도 그리지 않는다.

- `수련 ★` / `수련 ★★` / `수련 ★★★`
- 위치는 `.card-crown`의 이름 아래. 컬렉션 축소 카드에서는 별만 표시한다.
- 색은 카드 속성색(`--type`)을 따른다.

### 3-2. 종합점수

종합점수는 이미 체력을 포함해 계산한다(`card-view.js`의 `totalScore`). 강화된 사본을 렌더에 넘기면 숫자가 저절로 오른다. **공식은 바꾸지 않는다.**

컬렉션 화면에서도 수련이 반영된 값을 보여 준다. 아이가 자기 카드가 자란 것을 도감에서 확인할 수 있어야 한다.

### 3-3. 승리 안내

결과 dialog(`index.html:181`)의 본문에 한 줄을 더한다.

- 단계가 오른 판: **"관우의 수련이 ★★가 되었어요! 체력 +20"**
- 오르지 않은 판: **"관우의 수련까지 2번 더 이기면 돼요"**
- 최대치: **"관우는 수련을 모두 마쳤어요"**

### 3-4. 상세 dialog

카드 상세에 남은 승수를 한 줄로 적는다. 잠긴 카드에는 표시하지 않는다.

## 4. 균형 확인 (구현의 일부다)

수련은 균형을 건드리는 기능이므로 **시뮬레이션 통과를 완료 조건에 넣는다.**

`cards/tests/` 에 검사를 추가한다. 51장 전원을 `getBalancedEnemyPool` 상대와 붙이되, **플레이어 카드에만 수련 3단계를 적용**하고 양쪽 AI로 끝까지 둔다. 시드는 기존 검사와 같은 방식으로 고정한다.

통과 기준.

1. 어떤 짝도 120행동 안에 끝난다. 교착 0건.
2. 수련 3단계 적용 시 어떤 카드도 승률 **95%를 넘지 않는다.**
3. 수련 0단계 대비 평균 승률 상승폭이 **10~25%p** 안에 든다. 너무 작으면 보람이 없고, 너무 크면 상대가 의미를 잃는다.
4. 원본 `cards.json`은 대결 전후로 바이트가 같다.

3번이 범위를 벗어나면 2-1의 보너스 값을 조정하고 다시 잰다. 이 문서의 숫자보다 측정값이 우선이다.

## 6. 완료 기준

1. 같은 카드로 한 번 이기면 수련 ★가 되고, 컬렉션에서 체력과 종합점수가 오른 것이 보인다.
2. 앱을 껐다 켜도 수련이 남아 있다.
3. 져도 수련이 줄지 않는다.
4. 6승이면 ★★★가 되고 그 뒤로는 오르지 않는다.
5. 3단계 카드의 가장 싼 피해 기술이 10 더 준다. 상세 화면의 숫자와 실제 피해가 같다.
6. `cards.json`이 바뀌지 않는다.
7. 4절의 네 가지 균형 기준을 모두 만족한다.
8. `node --test "cards/tests/*.test.js"` 가 어벤져스 서비스워커 건을 뺀 전부 통과.
9. 아이패드 세로·가로와 폰에서 배지가 카드 밖으로 나가거나 다른 글자를 가리지 않는다.

## 8. 이번 범위 밖

- 카드끼리 합쳐 강화하는 방식. 카드를 잃는 구조라 아이에게 맞지 않는다.
- 확률로 성공·실패하는 강화. 실패로 좌절을 만들지 않는다.
- 수련 초기화 버튼. 필요해지면 그때 정한다.
- 별점(공격·방어·지력)을 실제 전투에 반영하는 작업. 별건이며 51장 균형을 다시 잡아야 한다.
