# 재이의 운동회 — 그림 규격 (ART-SPEC.md)

방식: **미리 그린 고품질 그림 + 프레임 애니메이션을 2.5D 무대(Canvas2D)에 올린다.** 그림 파일이 들어오면 코드 수정 없이 `art/manifest.json` 만 고치면 바뀐다(없는 동안은 허브 3D 아이 그림 한 장 + 코드 늘이기로 자리표시).

## 1. 아이 동작 아틀라스

- 선수: `jaei` 재이(청군: 파란 머리띠·남색 반바지) · `taeo` 태오(백군: 흰 머리띠·빨간 반바지) 둘뿐(대표님 11-20). 생김새·옷은 `src/kids.js` 의 `look`.
- 들어온 것: `art/jaei/jump.*`(43프레임, contact 3·top 32) · `art/taeo/jump.*`(40프레임, contact 8·top 21) — 60fps, 줄이 그림 안. `art/<kid>/stand.webp` = jump 0번 프레임(화면 초상·시상대). 태오는 `kids.js` `scale: 0.86` 으로 재이보다 작게(원본 키 비율 1060:1268).
- 다른 종목(야구·훌라후프·축구·농구) 동작 클립은 아직 없다 → 그 종목은 이 두 아이의 jump 아틀라스 한 프레임(Actor 자동 대체) + 코드 몸짓(기울이기·늘이기·소품)으로 먼저 만들고, 클립이 오면 manifest 에 동작 이름만 더한다.
- 파일: `art/<kid>/<action>.webp`(투명 배경 WebP, 프레임을 격자로 붙인 한 장) + `art/<kid>/<action>.json`
- 캐릭터 키: 프레임 안에서 **360~480px**. 동작당 **12~24프레임**. 모든 동작이 같은 배율(키가 동작마다 달라지지 않게).
- 시점: 정면에서 살짝 비스듬히(3/4). 종목 공용 동작은 정면, 종목 동작은 그 종목 화면 방향(아래 표).

```json
{
  "frames": [ { "x": 0, "y": 0, "w": 300, "h": 480 }, ... ],
  "fps": 18,
  "anchor": { "x": 150, "y": 470 },
  "height": 450,
  "loop": true,
  "events": { "contact": 9, "top": 30 },
  "rope": true
}
```
- `anchor` = 발(땅에 닿는 점), 프레임 안 픽셀. 모든 프레임에서 같은 점이 발이 되게 맞춰 자른다(프레임마다 다르면 프레임에 `ax, ay` 를 넣는다 — 다음 단계에서 지원).
- `height` = 캐릭터 키 픽셀(없으면 가장 큰 프레임 높이).
- `events.contact` = 공·줄과 닿는 프레임 번호(스윙·킥·슛, 줄넘기는 줄이 발밑을 지나는 프레임). 코드는 이 순간에 맞춰 소품·판정을 맞춘다.
- 줄넘기 `jump` 에 줄이 그려져 있으면 `"rope": true` + `events.top`(줄이 머리 위 가장 높은 프레임). 그러면 코드는 줄을 따로 그리지 않고, **게임의 줄 각도로 프레임을 고른다**(contact = 발밑, top = 머리 위, 그 사이는 따로 늘여 맞춤). 아이가 톡 했을 때의 점프는 코드가 몸을 살짝(키의 20%) 띄워 보인다. 무지개 줄(문제 보상)·금빛 줄(2단 기회)은 몸 둘레 빛 테 + 줄 자리 반짝이로 보인다.
- `loop`: idle·cheer·spin = true, 나머지 = false.

| action | 쓰는 곳 | 길이·느낌 | 코드가 프레임을 고르는 법 |
|---|---|---|---|
| `idle` | 모든 화면 | 숨쉬기·살짝 흔들 2초 루프 | 시간 |
| `cheer` | 성공·우승·시상대 | 만세 폴짝 1초 루프 | 시간 |
| `sad` | 실수·졌을 때 | 아쉬워 0.8초 | 시간(한 번) |
| `run` | 달려 들어가기(꼬마 기차) | 제자리 달리기 루프 | 시간 |
| `jump` | 줄넘기 | 줄이 든 한 바퀴 루프(rope:true) 또는 쪼그림→도약→착지 | rope:true = **줄 각도**, 아니면 점프 높이(`scrub`) |
| `swing` | 야구 | 준비→휘두름(contact)→마무리, 옆모습 | 진행도 = 스윙 각도 |
| `spin` | 훌라후프 | 엉덩이 돌리기 한 바퀴 루프 | 진행도 = 후프 각도 |
| `kick` | 축구 | 디딤→차기(contact)→마무리 | 진행도/시간 |
| `shoot` | 농구 | 무릎 굽혀→던짐(contact)→손목 | 진행도/시간 |

손에 든 줄 손잡이·배트·후프·공은 **그리지 않는다**(코드가 그린다). 손 위치가 필요한 동작(jump·swing·shoot)은 json 에 `"hands": [{ "l": {x,y}, "r": {x,y} }, ...]`(프레임마다)를 넣으면 다음 단계에서 소품을 손에 붙인다.

## 2. 배경(종목마다)

### 2-1. 한 장짜리 그림판(지금 쓰는 방식)
- 파일: `art/bg/<이름>.webp` 약 1920×1080(PNG 원본을 WebP q80 으로). 들어온 것: `art/bg/field.webp`(학교 운동장).
- manifest `plates.<이름> = { "file": "bg/field.webp", "ground": 0.93, "kidH": 0.45 }`: 그림 높이의 `ground` 비율 지점이 아이 발(땅), 아이 키가 그림 높이의 `kidH` 가 되게 놓는다. 화면을 꽉 채우게(cover) 카메라가 묶인다(경기 중엔 그림 밖이 안 보임).
- `backgrounds.<eventId> = { "plate": "field" }`(lobby 도 같은 그림판).
- 첫 화면 시연만 메뉴를 피하려고 그림 밖까지 갈 수 있다: 양옆 = 좌우 뒤집은 그림, 위·아래 = 맨 위·맨 아래 줄 평균색.

### 2-2. 시차 층(나중에 원하면)
- 파일: `art/bg/<eventId>/<layer>.webp`, 크기 약 **1920×1080**(가로 반복이 되게 좌우 끝이 이어지면 좋다).
- 층과 시차: `sky`(0.05, 하늘·구름) → `stands`(0.35, 관중석 건물) → `field`(1, 땅·코트) → `fore`(앞쪽 장식, 다음 단계).
- 그리는 위치: 층 그림 세로 1400 world 를 화면 world y −1000~+400 에 맞춘다 → **그림 세로 71% 지점이 땅(y=0)**. 관중석 아래 끝은 그림 세로 약 40% 근처.
- 관중 띠: `art/bg/crowd.webp` 가로로 이어지는 관중(투명 배경, 세로 약 260px). 코드가 세로 조각으로 잘라 파도·들썩임을 준다.
- eventId: `jumprope`, `baseball`, `hula`, `soccer`, `basketball`, `lobby`(경기장·시상식 뒤).

## 3. manifest.json

```json
{
  "version": 2,
  "kids": { "jaei": ["jump"], "taeo": [] },
  "plates": { "field": { "file": "bg/field.webp", "ground": 0.93, "kidH": 0.45 } },
  "backgrounds": { "jumprope": { "plate": "field" }, "lobby": { "plate": "field" } },
  "crowd": false
}
```
- 동작 아틀라스가 없는 동작(idle·cheer·sad)은 같은 아이의 다른 진짜 아틀라스 한 프레임 + 코드 숨쉬기·폴짝으로 대신한다(옷차림이 섞이지 않게). 진짜 그림이 하나도 없는 아이만 허브 3D 아이 그림으로 대신.
- 목록에 있는 것만 읽는다(없는 파일은 요청도 안 함 → 404 없음). 같은 이름으로 그림을 바꾸면 `version` 을 올린다(`?v=` 가 바뀌어 기기 캐시가 새로 받는다).
- 새 그림 파일은 `sw.js` OPTIONAL_SHELL 에도 `./sports/art/...?v=<version>` 으로 넣는다.

## 4. 제작 메모

- 투명 배경: 영상에서 뽑은 프레임은 크로마키 후 가장자리 1~2px 흰 테두리 정리. 허브 아이 그림처럼 **흰 스티커 테두리(약 4px)** 를 두르면 어떤 배경에서도 또렷하다.
- 아이 얼굴·이름은 가족 허브 전용(공개 앱판에 넣지 않는다).
- 용량: 동작 한 장 300KB 이하 목표(WebP q80). 아이 넷 × 동작 9 ≈ 36장.
