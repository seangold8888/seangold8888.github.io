# 재이의 수학놀이터 — DESIGN.md

> 재이가 스스로 시작하고, 어려운 문제에서도 다시 생각하며, 내일 돌아오고 싶은 작은 정원.

버전 1.1 · 2026-09-08 · 적용 범위: `/math/`의 모든 아이 화면과 부모님 화면.

이 문서는 v20 구현을 바탕으로 한 프로젝트 전용 디자인 기준이다. **현재 구현값, 이후 적용할 규칙, 아직 남아 있는 차이를 구분한다.** 문서를 작성했다고 CSS와 화면이 바뀌는 것은 아니다. 차이는 11번 정비 목록에 기록한다.

## 1. 제품의 목적과 인상

공식 서비스 이름은 **재이의 수학놀이터**다. 화면 제목·브라우저 제목·부모 화면·인쇄물에 이 표기를 사용한다. 정원은 배경 테마이며 서비스 이름을 대신하지 않는다.

사용자는 초등학생 재이와 보호자다. 핵심 행동은 수학을 시작하고, 생각하고, 해결하는 것이다.

- 분위기: 해 질 무렵의 정원, 부드러운 펠트와 점토, 따뜻한 불빛, 차분한 보랏빛.
- 화면 구조: 그림으로 초대하고, 밝은 면에서 읽고 생각하며, 작은 변화로 성취를 보여준다.
- 시선 순서: 현재 할 일 → 실행 버튼 또는 문제 → 도움 → 보상과 부가 기록.
- 장식 밀도: 홈·결과에서는 풍부하게, 문제 영역에서는 낮게, 부모 기록에서는 최소화한다.
- 한 화면의 주된 실행 버튼은 하나다. ‘모험 시작’ 옆 ‘3문제’는 보조 버튼이다.
- 같은 기능은 같은 이름·색·모양을 유지한다. 색상은 동작과 상태에 의미가 있어야 한다.

상태색은 장식색과 구분한다. 성공·도움·주의의 글자는 읽을 수 있는 진한 색을 선택하고 배경은 연하게 둔다. 기존 `style.css`의 `--ok`, `--no` 등은 상태 토큰 정비 대상이다.

- 보라: 주 행동·선택. 초록: 성장·해결. 베이지: 도움.
- 오답을 커다란 빨간 면이나 경고창으로 표현하지 않는다.
- 선택·성공 여부는 색에 더해 테두리·아이콘·문구로 구별한다.
- 일반 글자 대비 4.5:1 이상, 큰 글자와 의미 있는 UI 경계 3:1 이상을 프로젝트 목표로 검사한다. 현재 전체 화면이 통과했다는 뜻은 아니다.
- 이미지 위 글자는 일정한 어두운 오버레이 위에 둔다. 사진의 우연한 어두움에 의존하지 않는다.

## 4. 타이포그래피

### 서체 역할

- 한국어 제목·아이 안내·짧은 버튼: `Jua`, `Apple SD Gothic Neo`, `Malgun Gothic`, system-ui, sans-serif. Jua는 기본 400을 사용한다.
- 계산식·키패드·숫자 기록: `Nunito` 800 또는 900, `Jua`, system-ui. `font-variant-numeric: tabular-nums`를 유지한다.
- 부모 화면의 긴 문단과 표: 시스템 한국어 sans-serif로 읽기 편하게 정비한다. 단위와 숫자 정렬을 유지한다.
- 새 폰트를 추가하기 전에 한국어 지원·실제 로드 굵기·폰트 실패 시 줄바꿈을 확인한다.

### 현재 크기와 유지할 위계

| 용도 | 넓은 화면 | 600px 이하 | 행간 / 원칙 |
|---|---|---|---|
| 브랜드 제목 | 23px | 19px | 짧은 한 줄, 필요하면 이름 배지 재배치 |
| 정원 제목 | 39px | 31px | 1.28, 최대 2~3줄 |
| 미션 제목 | 25px | 22px | 긴 설명을 제목에 넣지 않음 |
| 계산식 | 40px | 34px | 1.5, 기호를 명확하게 구분 |
| 문제 안 한국어 | 25px | 22px | 의미 단위로 줄바꿈 |
| 키패드 숫자 | 29px | 27px | 일정한 폭과 정렬 |
| 주요 버튼 | 19~21px | 16px 이상 | 누름 영역을 먼저 확보 |
| 필수 아이 안내 | 목표 16~18px | 목표 16px 이상 | 1.5~1.65 |
| 부모 본문 | 목표 14~16px | 목표 14px 이상 | 1.55~1.65 |
| 비필수 캡션 | 12~13px 권장 | 12px 이상 권장 | 작은 글자에 핵심 지시를 숨기지 않음 |

한국어는 `word-break: keep-all`을 우선 고려하고 아주 긴 이름만 안전하게 줄바꿈한다. 숫자·수식·답 입력은 이미지에 그리지 않는다. 음수 자간은 큰 제목에 제한한다. 확대를 막지 않으며 200%에서도 문제·힌트·확인 버튼을 사용할 수 있어야 한다.

## 5. 여백·반경·그림자

| 항목 | 기준 |
|---|---|
| 아이 홈·옷장 최대 폭 | 920px |
| 집중 화면 최대 폭 | 620px: 시작·진단·문제·캡슐·결과·칭찬 |
| 부모 화면 최대 폭 | 1000px |
| 페이지 좌우 여백 | 데스크톱 24px / 모바일 14px |
| 카드 내부 여백 | 데스크톱 22px / 모바일 18px |
| 주 행동 버튼 사이 | 12px / 모바일 9px |
| 관련 요소 간격 | 8~12px |
| 새 섹션 사이 | 24~32px |
| 카드 반경 | 22px |
| 정원 이미지 반경 | 데스크톱 30px / 모바일 24px |
| 주 버튼 반경 | 15px / 모바일 홈 버튼 13px |
| 입력칸·답칸 반경 | 목표 12px |
| 숫자 버튼 반경 | 14px |
| 작은 도움 버튼·배지 | pill, 999px |

새 간격은 `4, 8, 12, 16, 24, 32, 40` 계열에서 먼저 선택한다. 현재 14·18·22px처럼 화면에 맞춰 정한 값은 명시된 컴포넌트에서 유지한다. 같은 컴포넌트에 임의의 치수를 늘리지 않는다.

- 일반 카드 그림자: `0 8px 30px #45345f09`.
- 정원 장면 그림자: `0 14px 35px #45345f18`.
- 주 버튼: `0 4px 0 #584885`; 누르면 `translateY(3px)`와 `0 1px 0 #584885`.
- 부모 표·배지·숫자 주변에 겹겹이 그림자를 넣지 않는다.
- 단순 정보 카드에는 가짜 hover나 손가락 커서를 붙이지 않는다.

## 6. 컴포넌트와 상태 계약

| 컴포넌트 | 기본 | 반응 및 상태 |
|---|---|---|
| 주 버튼 | 보라 배경, 흰 글자, 눌림 받침 | hover는 미세한 명도 변화. pressed는 3px 하강. 처리 중 중복 실행 방지 |
| 보조 버튼 | 연보라 면, 진한 보라 글자 | 주 버튼과 같은 높이·반경. 주 버튼보다 낮은 강조 |
| 도움 버튼 | 베이지 pill, 행동을 말하는 문구 | ‘힌트 → 그림 → 풀이’ 단계에 맞춰 문구 변경 |
| 키패드 | 고정 숫자 배치와 일정한 누름 영역 | 확인은 보라, 지우기는 보조색. 결과 중복 저장 금지 |
| 답 입력칸 | 연한 면과 선명한 하단 경계 | 정답은 성공색과 문구. 오답 시 다음 도움 단계 표시 |
| 씨앗 모형 | 주어진 씨앗은 초록, 추가한 씨앗은 분홍 | 추가/취소 시 `aria-pressed` 갱신. 주어진 칸과 조작 가능한 칸 구별 |
| 친구·옷 선택 | 동일한 외곽과 썸네일 비율 | 선택은 테두리와 ‘입는 중/선택됨’ 문구. 접근성 상태도 갱신 |
| 옷장 탭 | 가로 스크롤 가능한 한 줄 | 선택된 탭과 화면 밖의 추가 탭을 이해할 수 있게 표시 |
| 구매 상태 | 가진 것 / 살 수 있는 것 / 더 모을 것 | 이름·가격·행동을 함께 표시. 자물쇠나 색만으로 전달하지 않음 |
| 폼 필드 | 항상 보이는 라벨, 충분한 입력 크기 | focus·입력 오류·완료를 안내. placeholder를 유일한 라벨로 쓰지 않음 |
| 개념 기록 | 아직 안 함 / 연습 중 / 다른 날에도 해결 | 실제 기록만 표시. 상태색과 문구를 함께 사용 |
| 보상 | 꽃·발견·코인·스티커 | 한 번의 완료에 한 번 반영. 받지 않은 보상을 받은 것처럼 표시하지 않음 |

모든 조작 요소의 목표 누름 영역은 최소 44×44px다. 수학 입력과 주 행동은 48px 이상을 우선한다. 글자가 작아져도 누름 영역까지 축소하지 않는다.

포커스는 3px `#367c99`, offset 4px를 기준으로 한다. 비활성 상태는 시각 표현과 실제 `disabled`를 함께 적용한다. 이유가 필요한 경우 근처 문구로 설명한다. 구매 가능 상태와 선택 상태가 서로 덮어쓰지 않게 한다.

## 7. 화면별 적용

| 화면 | 가장 먼저 보일 것 | 유지할 규칙 |
|---|---|---|
| 처음 방문 | 짧은 환영, 3문제 시작 | 이름 선택. 학교 입력은 부모 화면. 진단을 유일한 시작점으로 만들지 않음 |
| 진단 | 문제와 입력 | 작은 상단 장면. 연습용 도움과 진단의 평가 조건을 혼동하지 않음 |
| 홈 | 오늘 할 일, 시작/이어하기 | 기본 글자 크기의 390×844 화면에서 주 행동이 첫 화면 안에 보이게 유지 |
| 문제 | 식, 입력, 피드백 | 그림을 식 뒤에 두지 않음. 현재 문제 곁에 도움 표시 |
| 힌트 | 다음에 생각할 작은 단계 | 모형과 정적 그림의 중복을 줄여 키패드를 과도하게 밀지 않음 |
| 복귀 | ‘하던 모험 이어하기’, 진행 위치 | 도움 사용과 완료 기록 유지. 환영 문구로 재시작 부담 완화 |
| 캐릭터·옷장 | 현재 친구, 코인, 아이템 | 공통 버튼 체계. 상품 비율과 가격 위치 일정 |
| 캡슐·결과 | 받은 보상과 오늘의 발견 | 핵심 버튼을 계속 흔들지 않음. 끝내기와 선택적 추가 학습의 위계 유지 |
| 부모 칭찬 | 오늘 실제로 한 행동 | 기록에 없는 풀이 전략을 칭찬 문구로 만들어내지 않음 |
| 부모 기록·설정 | 개념별 기록과 조정 | 같은 팔레트, 낮은 장식 밀도. 표는 읽기·복사 가능. 단위와 빈 상태 명확 |
| 종이 문제지 | 문제와 쓰기 공간 | 장식·실행 버튼 숨김. 흑백 인쇄에서도 문제 구분 가능 |

## 8. 인터랙션과 문구

- 조작에 대한 변화는 즉시 드러내고 필요한 피드백을 함께 보여준다.
- 전환·hover 목표 시간은 120~180ms. 정답 축하는 350~800ms 안에서 짧게 끝낸다.
- 정답·힌트 피드백을 스크린리더로 이해할 수 있게 한다. 기존 `#feedback`의 `role="status"`, `aria-live="polite"`를 유지한다.
- `prefers-reduced-motion: reduce`에서는 장식 애니메이션과 불필요한 이동을 끈다.
- 색종이·꽃·별을 동시에 계속 움직이지 않는다. 정답을 읽는 동안 화면이 흔들리지 않아야 한다.
- 쉬기·새로고침 후 도움을 본 기록을 독립 정답으로 바꾸지 않는다.
- 오답 문구는 다음 행동을 알려준다: ‘10을 먼저 만들어 볼까요?’, ‘그림으로 같이 생각해 봐요.’
- 아이에게 계획 지연·등수·속도 경쟁을 강조하지 않는다. 실제 확인한 배움을 축하한다.
- 버튼에는 실제 행동 이름을 쓴다. 장식용 영어 문구를 추가하지 않는다.

## 9. 반응형과 이미지

- 600px 이하: 한 열, 14px 좌우 여백, 300px 홈 장면, 18px 카드 안쪽 여백.
- 601~759px: 한 열을 유지하고 가용 폭을 활용한다.
- 760px 이상: 홈의 캐릭터와 길잡이는 두 열이 가능하다. 문제 풀이는 620px에 집중한다.
- 부모 표·옷장 탭·배움 지도처럼 필요한 곳만 가로 스크롤한다. 페이지 전체의 가로 넘침은 허용하지 않는다.
- 큰 글씨나 긴 문구로 두 열 버튼이 무너지면 한 열로 바꾼다. 글자를 잘라 맞추지 않는다.
- 기준 장면: `assets/garden-hero.webp` (1536×1024). 제작 기록: `assets/garden-art.md`.
- 새 장면은 동일한 조명·재질·팔레트·캐릭터 비율을 유지한다.
- 홈에서는 장면을 풍부하게, 문제에서는 작은 크롭만 사용한다.
- 얼굴과 중요한 행동이 모바일에서 잘리지 않게 이미지 위치를 확인한다.
- 숫자·식·설명·버튼은 실제 HTML로 렌더링한다.
- 이미지를 최적화한다. 이미지가 로드되지 않아도 제목과 시작 버튼은 사용할 수 있어야 한다.
- 장식의 중복 낭독은 피하고, 문제 이해에 필수인 그림에는 의미 있는 설명을 제공한다.

## 10. AI 에이전트의 작업 순서

1. `DESIGN.md`와 `README.md`에서 해당 화면의 목적·학습 제약을 읽는다.
2. `style.css`와 뒤에 로드되는 `garden.css`의 해당 선택자를 함께 확인한다.
3. 기존 `.btn`, `.card`, `.field`, `.keypad`, `.help-btn`을 재사용한다. 같은 역할의 새 변형을 불필요하게 만들지 않는다.
4. 선택자 우선순위를 확인한다. 뒤의 `.box`가 앞의 `.problem .box`를 항상 덮어쓰는 것은 아니다.
5. HTML·JS의 id와 이벤트 연결을 보존한다. 디자인 정리 때문에 저장 구조나 숙달 기준을 바꾸지 않는다.
6. 같은 컴포넌트를 사용하는 화면에서 기본·선택·도움·완료·비활성 상태를 점검한다.
7. 기록 관련 기능을 바꾸면 이전 데이터와 이어하기를 검사한다. 실제 UI 배포에서는 CSS/JS 캐시 버전을 함께 갱신한다.

## 11. v20과 목표 기준 사이의 정비 목록

문서 작성 시 확인한 차이다. **아래 작업은 아직 문서만으로 적용되지 않았다.** 다음 UI 수정에서 해당 컴포넌트를 만질 때 함께 정비한다.

- 공통 치수가 여러 위치에 반복된다. 의미별 토큰을 도입하고 중복 선언을 줄인다.
- `.problem .box`가 `garden.css`의 `.box`보다 우선한다. 목표 12px 반경과 면색의 실제 적용을 확인한다.
- 기존 키패드 `nth-child` 배경이 새 일반 버튼 배경보다 우선할 수 있다. 숫자 장식색과 확인 버튼의 의미색을 정리한다.
- 옷장 탭·아이템 선택색과 그림자에 이전 테마 값이 남아 있다. 공통 선택·주 행동 위계로 맞춘다.
- 상태색과 부가 설명의 전체 대비 검사는 아직 하지 않았다. 실제 조합을 측정한다.
- 일부 필수 안내는 14~15px, 정원 캡션은 10~11px다. 역할을 구분해 목표 크기로 조정한다.
- 씨앗 칸은 최소 39px, 도움 버튼은 42px, 색상 스와치는 30px다. 최소 44px 조작 영역을 확보한다.
- 포커스 선택자에 텍스트 입력·textarea까지 포함하고 옷장 선택·탭 상태의 접근성 표현을 정비한다.
- 부모의 긴 본문에 아이용 서체가 상속된다. 읽기용 서체 역할을 분리한다.
- 320px 폭, 200% 확대, 긴 이름, 폰트·이미지 로드 실패 조건을 추가로 확인한다.
